## Rationale

The legacy PPO passed infrastructure use but failed promotion because artifact completeness does not prove trading edge.

Positive Sharpe alone does not prove edge.

Cash outperformance alone does not prove edge.

The buy-and-hold evidence was mixed:

```text
complete_artifact_rows_audited = 18
complete_artifact_rows_beating_buy_and_hold = 8
complete_artifact_rows_underperforming_buy_and_hold = 10
median_ppo_vs_buy_and_hold = negative
```

Candidate-set stability was not established in no-submit observation.

Multi-order instability remained unresolved.

Controlled submit requires a separate checkpoint and is rejected for the legacy PPO.

## Legacy PPO Final Classification

The legacy PPO baseline remains valid only for:

```text
artifact-loading validation
feature-alignment validation
prediction-pipeline validation
broker connectivity validation
NO-SUBMIT safety validation
reporting-chain validation
audit baseline comparison
future PPO v2 benchmark comparison
```

The legacy PPO baseline is not valid for:

```text
controlled paper submit
live trading
hybrid deployment
claiming trading edge
feature-importance based promotion
production readiness
```

## Hybrid Model Decision

## Retraining Design Decision

Do not retrain the legacy PPO model directly.

Proceed only to v1.66 PPO v2 Retraining Design.

v1.66 may design the retraining plan, data requirements, walk-forward protocol, costs, benchmarks, leakage controls, model selection rules, and promotion gates.

v1.66 must not execute retraining unless a later checkpoint authorizes it.

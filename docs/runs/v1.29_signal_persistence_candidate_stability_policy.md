# v1.29 Signal Persistence / Candidate Stability Policy

Date: 2026-06-09  
Status: Completed  
Mode: Policy / documentation checkpoint  

## Purpose

Create a formal policy defining when a model-generated candidate is stable enough to be considered for a future controlled submit.

This checkpoint follows:

```text
v1.28 Controlled Submit Decision / No-Submit Outcome
```

## Background

v1.27 identified a fresh single-order candidate:

```text
UNH sell
```

v1.28 required a fresh revalidation before any submit decision.
The fresh v1.28 plan did not produce a UNH sell. Instead, the candidate changed to:

```text
AMD buy
```

The correct v1.28 decision was:

```text
NO-SUBMIT
```

## Files Added

```text
docs/workflows/signal_persistence_candidate_stability_policy.md
```

## Policy Scope

The policy defines:

```text
candidate persistence
candidate stability levels
changed candidate conditions
no-submit conditions
controlled submit eligibility requirements
documentation requirements
```

## Key Decision

A one-time candidate is not trade approval.
A candidate must be revalidated on a fresh future run before any controlled submit decision.
If the candidate changes symbol or side, the correct default action is:

```text
NO-SUBMIT
```

## Candidate Stability Levels

```text
Level 0 = one-time candidate; review only
Level 1 = revalidated candidate; eligible for controlled review
Level 2 = submit-eligible candidate; requires full safety stack and manual approval
```

## v1.28 Case Captured

The policy explicitly captures the v1.28 case:

```text
v1.27 candidate = UNH sell
v1.28 fresh candidate = AMD buy
Decision = no-submit
Reason = candidate did not persist
```

## Guardrails

Do not submit stale candidates.
Do not submit changed candidates.
Do not submit from prior checkpoint plans.
Do not submit from unfiltered multi-order plans.
Do not treat candidate identification as trade approval.
Future controlled submit decisions must still require:

```text
fresh dry run
risk controls pass
checklist pass
single-order filter if needed
--max-plan-age-minutes 90
--confirm-run-dir <exact reviewed run dir>
manual approval
broker verification after submit
documentation
```

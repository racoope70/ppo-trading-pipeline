## 2. Temporal Boundary Convention Remediation

Blocking finding addressed:

temporal endpoint inclusivity/exclusivity undefined

temporal_boundary_convention = start_inclusive_end_exclusive

Justification:

The start-inclusive/end-exclusive convention avoids overlap at exact boundary timestamps and creates deterministic window assignment. Under this convention, a row whose Datetime equals a window start is eligible for that window, while a row whose Datetime equals that same window end is not assigned to that window.

Rows are assigned only after feature generation, warm-up/drop handling, and final timestamp normalization.

Embargo rows are excluded from train/evaluation/holdout output assignments.

### Train Boundary Rule

train_window_start = 2023-01-03T14:30:00Z
train_window_end = 2024-06-14T20:00:00Z
train_rule = Datetime >= train_window_start and Datetime < train_window_end

Rows exactly equal to 2023-01-03T14:30:00Z are assigned to train if all other requirements pass.

Rows exactly equal to 2024-06-14T20:00:00Z are not assigned to train under this convention.

### Train/Evaluation Embargo Boundary Rule

train_eval_embargo_start = 2024-06-17T13:30:00Z
train_eval_embargo_end = 2024-06-21T20:00:00Z
train_eval_embargo_rule = Datetime >= train_eval_embargo_start and Datetime < train_eval_embargo_end

Rows exactly equal to 2024-06-17T13:30:00Z are embargo rows.

Rows exactly equal to 2024-06-21T20:00:00Z are not assigned to the train/evaluation embargo under this convention.

Embargo rows are excluded from train, evaluation, and holdout output assignments.

### Evaluation Boundary Rule

evaluation_window_start = 2024-06-24T13:30:00Z
evaluation_window_end = 2024-12-13T21:00:00Z
evaluation_rule = Datetime >= evaluation_window_start and Datetime < evaluation_window_end

Rows exactly equal to 2024-06-24T13:30:00Z are assigned to evaluation if all other requirements pass.

Rows exactly equal to 2024-12-13T21:00:00Z are not assigned to evaluation under this convention.

### Evaluation/Holdout Embargo Boundary Rule

eval_holdout_embargo_start = 2024-12-16T14:30:00Z
eval_holdout_embargo_end = 2024-12-20T21:00:00Z
eval_holdout_embargo_rule = Datetime >= eval_holdout_embargo_start and Datetime < eval_holdout_embargo_end

Rows exactly equal to 2024-12-16T14:30:00Z are embargo rows.

Rows exactly equal to 2024-12-20T21:00:00Z are not assigned to the evaluation/holdout embargo under this convention.

Embargo rows are excluded from train, evaluation, and holdout output assignments.

### Holdout Boundary Rule

holdout_window_start = 2024-12-23T14:30:00Z
holdout_window_end = 2025-06-30T20:00:00Z
holdout_rule = Datetime >= holdout_window_start and Datetime < holdout_window_end

Rows exactly equal to 2024-12-23T14:30:00Z are assigned to holdout if all other requirements pass.

Rows exactly equal to 2025-06-30T20:00:00Z are not assigned to holdout under this convention.

### Window Precedence Rule

window_assignment_precedence =
1. reject invalid or duplicate rows
2. apply feature generation and warm-up/drop policy
3. identify embargo rows and exclude them from train/evaluation/holdout assignments
4. assign remaining rows using start-inclusive/end-exclusive train, evaluation, and holdout rules
5. rows outside all named output windows remain unassigned and must be reported in evidence

temporal_boundary_convention_remediation = PASS

## Calendar runtime treatment

Deferred calendar runtime verification is acceptable for documentation-level final contract resolution and independent review.

It is not acceptable for implementation authorization.

Before implementation authorization can be reconsidered, a separately authorized verification must confirm:

- the installed `exchange-calendars` version equals 4.13.2;
- `get_calendar("XNYS")` succeeds;
- the complete reconstruction range is covered;
- opens and closes are timezone-aware UTC;
- representative holidays are excluded;
- representative early closes are correct;
- whole-interval containment produces governed slot counts;
- repeated schedule construction is deterministic; and
- transitive dependency versions are recorded.

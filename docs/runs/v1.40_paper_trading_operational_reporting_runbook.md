## Runbook Scope

The runbook documents the standard reporting chain:

```text
decision-state hook
run summary with decision state
dashboard with decision state
reporting chain smoke test
artifact verification
failure handling
no-submit guardrails
```

## Standard Reporting Commands

The runbook standardizes these commands:

```bash
python -m src.paper_trading.pipeline_decision_state_hook \
  --run-dir reports/paper_trading_dry_runs/latest \
  --prior-symbol AMD \
  --prior-side buy

python -m src.paper_trading.build_run_summary_with_decision_state \
  --run-dir reports/paper_trading_dry_runs/latest

python -m src.paper_trading.build_decision_dashboard_with_state \
  --run-dir reports/paper_trading_dry_runs/latest

python -m src.paper_trading.reporting_chain_smoke_test \
  --run-dir reports/paper_trading_dry_runs/latest \
  --prior-symbol AMD \
  --prior-side buy
```

## Expected Safe Output

The expected default reporting output is:

```text
decision = NO_SUBMIT
submit_allowed = False
```

## Failure Handling Added

The runbook documents how to respond to:

```text
missing pre_trade_checklist_report.json
failed smoke test
unexpected submit_allowed = True
unexpected non-NO_SUBMIT decision
artifact mismatch
```

## Safety Design

The runbook explicitly states that the reporting chain does not:

```text
connect to Alpaca
submit orders
alter broker state
change execution plans
approve trades
replace manual review
```

## Interpretation

v1.40 turns the reporting utilities from ad hoc commands into a repeatable operating procedure.
This improves auditability and makes future paper-trading reviews easier to reproduce.

## Guardrails

The reporting chain is not a submit checkpoint.
A future controlled submit still requires:

```text
fresh dry run
evaluation pass
risk controls pass
pre-trade checklist pass
single-order reviewed directory
manual approval
--max-plan-age-minutes 90
--confirm-run-dir <exact reviewed run dir>
broker verification after submit
documentation
```

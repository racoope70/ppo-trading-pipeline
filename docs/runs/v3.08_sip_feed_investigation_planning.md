## 6. SIP investigation questions

A future SIP investigation would need to answer:

- Is SIP historical-data access available in the current Alpaca account and environment?
- Do SIP entitlement, cost, subscription, licensing, or usage restrictions apply?
- Must SIP be treated as a separate feed identity and separate contract branch?
- Could SIP recover the exact missing symbol/timestamp observations that IEX did not recover?
- Would SIP introduce different timestamp/session semantics, coverage, adjustment, or provenance implications?
- How would SIP evidence be isolated from existing IEX evidence?
- What would count as success, partial success, or a fail-closed outcome?
- What records and checksums would be required if a future SIP candidate were authorized?
- Which downstream milestones would remain blocked even if SIP recovered observations?

## 8. Evidence isolation rules

Any future SIP investigation must keep SIP evidence isolated from IEX evidence:

- no overwriting the IEX raw parquet;
- no merging SIP into IEX data without separate authorization;
- no treating SIP data as replacement data by default;
- no treating SIP results as validated dataset evidence;
- no silently changing dataset identity;
- no byte-identical recovery claim;
- no historical-equivalence claim without separate evidence review; and
- no downstream use without separate authorization.

## 9. Fail-closed criteria

A future SIP execution, if ever separately authorized, should fail closed if:

- SIP entitlement is unavailable or uncertain;
- SIP cost or licensing is unresolved;
- the API request contract cannot be frozen before execution;
- credentials or account permissions are unclear;
- returned rows do not exactly match the 66 target observations;
- SIP returns partial results only;
- SIP timestamp semantics cannot be reconciled to the governed expected grid;
- SIP data quality or provenance cannot be documented;
- non-target rows would be required to make the candidate complete;
- source, test, or requirements changes appear necessary but are not separately authorized;
- a raw or candidate output path is not predeclared; or
- a checksum, manifest, or evidence boundary is not predeclared.

### Choice rationale

IEX is recommended because it is the executable default, appears in local provenance, and aligns with the Alpaca deployment path; SIP is a valid but materially different consolidated-feed alternative. RAW must be passed explicitly because omission is not an approved contract. The December 2022 retrieval start is a conservative policy buffer, not an alleged original date; only accepted observed bars count toward the 50-bar minimum.

`exchange_calendars`/XNYS is recommended for holiday, DST, and early-close session law. No exact version is locally installed or evidenced, so an exact reviewed version must be chosen before authorization rather than invented here. Provider timestamps remain aware UTC, are mapped to America/New_York/XNYS for session classification, and are finally stored as UTC. The market-open partial provider hour requires a precise reviewed overlap rule.

External documentation supports Alpaca bar-open, left-closed/right-open semantics. Provider labels must not be relabeled as bar close or silently converted into 09:30-aligned hourly windows. Expected labels must be compared per symbol/session; duplicates, interpolation, forward fill, zero-volume placeholders, and synthetic rows are prohibited; any missing expected bar fails closed.

The tracked runtime supports pandas 3.0.2 and PyArrow 24.0.0 for the new governed contract. The physical schema recommendation is: non-null uppercase Arrow UTF-8 `Symbol` without dictionary encoding; non-null `timestamp[ns, tz=UTC]` `Datetime`; non-null float64 OHLCV/features; configured column order; `Symbol, Datetime` row order; no serialized index; no final null/NaN/infinity; Snappy; Parquet 2.6; data-page 1.0; schema stored; statistics enabled; dictionary disabled; row group size 65,536.

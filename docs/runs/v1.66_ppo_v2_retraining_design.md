## Design Summary

The PPO v2 retraining design must define and document:

```text
data requirements
split design
walk-forward protocol
holdout rules
preprocessing controls
feature governance
cost and slippage assumptions
benchmark rules
model-selection rules
risk and robustness rules
artifact governance
promotion gates
rejection criteria
```

PPO v2 must be treated as a new governed candidate, not a continuation of the failed legacy PPO model.

The legacy PPO remains valid only as an infrastructure fixture, audit baseline, and future comparison point.

## Data Requirements

The planned data source is:

```text
Alpaca historical 1-hour stock bars
```

The planned baseline universe remains:

```text
AAPL
AMD
MRK
PFE
UNH
XOM
```

Any expansion beyond this six-ticker baseline requires a later checkpoint.

The retraining dataset design must include:

```text
explicit data provenance
timestamp coverage documentation
missing-bar checks
symbol-level coverage checks
corporate-action awareness
reproducible dataset generation
documented data extraction parameters
documented data storage paths
```

Generated datasets must remain excluded from version control unless a later checkpoint explicitly documents otherwise.

## Split Design

The PPO v2 training design must preserve strict temporal separation:

```text
train_df   = model fitting only
embargo    = temporal gap
eval_df    = walk-forward evaluation
holdout_df = untouched final validation
```

Required split rules:

```text
no temporal overlap
no leakage
embargo between train and eval
holdout remains untouched until final validation
no repeated tuning against holdout
no model promotion without holdout review
```

## Walk-Forward Protocol

PPO v2 must use a governed walk-forward design with multiple train/eval windows.

The walk-forward design must require:

```text
multiple train/eval windows
embargo between train and eval windows
symbol-level performance metrics
portfolio-level performance metrics
net-of-cost evaluation
consistent metric definitions across windows
no single-window cherry-picking
stable performance across windows before promotion
```

A future PPO v2 candidate must not be selected only because one window has strong performance.

## Holdout Rules

The holdout set must remain untouched until the final validation step.

The holdout set must not be used for:

```text
feature selection
normalization fitting
hyperparameter tuning
model selection
threshold tuning
candidate ranking
early stopping decisions
```

A model that fails holdout review cannot advance to paper-trading observation.

## Preprocessing and Normalization Controls

PPO v2 must use train-only preprocessing.

Required controls:

```text
fit preprocessing only on train_df
fit scaler statistics only on train_df
fit VecNormalize statistics only on train_df
lock training statistics for eval
lock training statistics for holdout
do not allow eval data to influence preprocessing
do not allow holdout data to influence preprocessing
```

Evaluation and holdout environments must use locked training statistics.

## Feature Governance

PPO v2 must use the safe feature manifest.

The following fields must not enter model feature inputs:

```text
Target
Return
Datetime
Symbol
```

These fields may be used only for labeling, grouping, evaluation, auditing, and reporting.

Feature additions require leakage review.

Feature importance cannot be used as proof of trading edge.

## Cost, Slippage, and Market Friction Assumptions

PPO v2 must be evaluated net of costs.

The design must document:

```text
commission or fee assumptions
slippage assumptions
spread or market-friction assumptions where available
turnover
trade frequency
sensitivity to higher-cost assumptions
```

A PPO v2 candidate must be rejected or redesigned if costs erase the apparent edge.

## Benchmark Requirements

PPO v2 must be compared against:

```text
cash / no-trade baseline
buy-and-hold baseline
equal-weight portfolio baseline where applicable
legacy PPO infrastructure baseline where applicable
```

Promotion cannot rely on positive Sharpe alone.

Promotion cannot rely on cash outperformance alone.

Promotion requires benchmark-relative evidence.

## Model-Selection Rules

PPO v2 model selection must be based on predeclared metrics.

Required model-selection evidence:

```text
majority-window support
positive median PPO-vs-buy-and-hold
acceptable drawdown
stable risk-adjusted returns
reasonable turnover
reasonable trade frequency
no unexplained single-symbol dependence
no single-window cherry-picking
```

Do not select a model based only on:

```text
best Sharpe
best single window
cash outperformance alone
feature importance
one favorable market regime
```

## Risk and Robustness Requirements

PPO v2 review must include:

```text
max drawdown review
turnover review
trade-frequency review
per-symbol performance review
portfolio-level performance review
regime sensitivity review where available
friction sensitivity checks
window-to-window stability review
```

A PPO v2 candidate must be rejected or redesigned if risk metrics are unstable or excessive.

## Artifact Governance

PPO v2 artifacts must use isolated directories.

Required artifact rules:

```text
do not overwrite legacy PPO artifacts
do not overwrite validated artifacts
document artifact paths before execution
keep generated models out of version control
keep generated datasets out of version control
keep generated reports and logs out of version control unless explicitly documented
preserve reproducibility through documented configuration
```

The legacy PPO artifact set remains an infrastructure fixture and audit comparison baseline.

## Promotion Gates

PPO v2 must follow the v1.64 promotion standard.

Required promotion levels:

```text
Level 0 = Infrastructure Baseline
Level 1 = Offline Model Quality Candidate
Level 2 = No-Submit Observation Candidate
Level 3 = Controlled-Submit Eligible Candidate
Level 4 = Production / Live Trading Candidate
```

v1.66 does not promote PPO v2 to any trading level.

v1.66 only designs the retraining plan.

## Rejection Criteria

Reject or redesign PPO v2 if:

```text
benchmark evidence is weak
median PPO-vs-buy-and-hold is negative
costs erase the edge
drawdown is excessive
turnover is excessive
leakage controls are incomplete
holdout is reused for tuning
performance depends on one window
candidate behavior is unstable
feature importance is used as proof of edge
cash outperformance is the only support
positive Sharpe is the only support
```

## v1.68 Planning Question

```text
How should the future PPO v2 retraining implementation be structured so that it remains controlled, auditable, leakage-safe, artifact-safe, and separated from training execution?
```

## Planned Configuration Requirements

The future PPO v2 configuration should define:

```text
canonical data source = Alpaca historical 1-hour stock bars
baseline universe = AAPL, AMD, MRK, PFE, UNH, XOM
train period
embargo period
evaluation period
holdout period
safe feature manifest
cost assumptions
slippage assumptions
turnover tracking
artifact root
report root
random seed policy
reproducibility controls
```

The configuration must include an explicit safety flag:

```text
training_execution_enabled = false
```

Training execution must remain disabled by default.

## Planned Data Controls

The future implementation plan must require:

```text
no generated datasets by default
no raw data committed
no processed data committed
documented data source
documented timestamp coverage
symbol-level coverage checks
missing-bar checks
duplicate-bar checks
market-session checks
corporate-action awareness
```

A later checkpoint must explicitly authorize any generated dataset creation.

## Planned Split Controls

The future implementation must enforce:

```text
train_df only for model fitting
embargo between train and eval
eval_df only for walk-forward evaluation
holdout_df untouched until final validation
no temporal overlap
no repeated tuning against holdout
no holdout leakage into preprocessing
no holdout leakage into model selection
```

## Planned Preprocessing Controls

The future implementation must require:

```text
fit scalers only on train_df
fit VecNormalize only on train_df
lock train statistics for eval
lock train statistics for holdout
eval_env.training = False
eval_env.norm_reward = False
```

## Planned Feature Controls

The future implementation must preserve the safe feature manifest.

The following fields must not enter PPO v2 feature inputs:

```text
Target
Return
Datetime
Symbol
```

These fields may be used only for:

```text
labeling
evaluation
grouping
auditing
reporting
```

## Planned Artifact Controls

The future implementation must define isolated PPO v2 paths before execution.

The plan must require:

```text
do not overwrite legacy PPO artifacts
do not overwrite validated artifacts
do not commit generated models
do not commit generated datasets
do not commit raw data
do not commit large reports
do not commit logs unless explicitly documented
do not commit credentials
```

Expected future artifact categories:

```text
raw data path
processed data path
model artifact path
training report path
walk-forward report path
holdout report path
audit summary path
```

v1.68 does not create these artifacts.

## Rejection Criteria for Future Implementation

The future implementation should be rejected or redesigned if:

```text

hybrid deployment is implied
```

## Key Policy Decision

A multi-order plan is not submit approval.
Even if risk controls pass and the checklist passes, a multi-order plan should not be submitted directly.

Default action:

```text
NO-SUBMIT
```

## Approved Multi-Order Options

Approved options:

```text
skip entire plan
document multi-order plan and stop
create one filtered candidate directory for review only
defer submit decision to a later checkpoint
```

Disallowed option:

```text
submit all orders directly
```

## Selection Priority for Future Review

If a future checkpoint filters one order from a multi-order plan, review priority should generally be:

1. Exit / reduce existing exposure
2. Risk-reducing rebalance
3. Larger notional only if risk-reducing
4. New entry only after separate review

## v1.30 Reference Case

v1.30 fresh plan:

```text
PFE buy = new entry
UNH sell = exit / reduce existing exposure
```

The v1.31 policy does not retroactively approve either order.
It only defines how future multi-order plans should be handled.

## Guardrails

Do not submit multi-order plans directly.
Do not treat passing risk controls as trade approval.
Do not mechanically select candidates without manual review.
Do not submit from stale plans.
Do not submit from documentation-only checkpoints.

Future controlled submit decisions still require:

```text
fresh dry run
single-order review or filtered candidate directory
risk controls pass
checklist pass
--max-plan-age-minutes 90
--confirm-run-dir <exact reviewed run dir>
manual approval
broker verification after submit
documentation
```

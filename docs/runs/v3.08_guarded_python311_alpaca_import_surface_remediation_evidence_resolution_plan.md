## Smallest governed evidence-resolution sequence

Each step below requires its own later, separately reviewed and explicitly
authorized evidence-gathering scope. Authorization of one step would not
authorize any later step or remediation.

1. **Installed identity evidence.** Define an exact read-only inspection of
   distribution identity and version inside the existing `.venv311` boundary.
   It must not enumerate unrelated packages, import modules, modify the
   environment, or access a package source.
2. **Compatibility evidence.** Define a separate bounded method to establish
   which exact package identity and version or bounded version constraint
   supports only the four preserved imports. Package-source inspection,
   package-index access, installation, and imports remain unauthorized unless
   separately proposed and approved.
3. **Source approval evidence.** Record the exact approved package source and
   its governance basis. A familiar or default package source must not be
   assumed.
4. **Command and boundary evidence.** After package identity, version, and
   source are resolved, draft the exact remediation command with an explicit
   `.venv311`-only boundary. Drafting does not authorize execution.
5. **Rollback evidence.** Define the exact rollback command and the exact
   pre-remediation state it would restore. Rollback must not depend on an
   unrecorded or inferred prior package state.
6. **Verification evidence.** Define one exact bounded verification command
   restricted to the four imports, with no client construction, credentials,
   account access, network access, API call, provider request, or market-data
   access.
7. **Evidence-record contract.** Define one sanitized record containing only
   approved categorical identities, command result classifications, bounded
   counters, and authorization state. It must exclude credentials, environment
   values, absolute paths, package contents, tracebacks, API material, and data.

## Implementation objectives

The future implementation should create a deterministic, fail-closed reconstruction path that can later produce the governed v3.08 dataset only after separate authorization.

Objectives:

1. Explicit Alpaca historical-bars request contract.
2. Explicit IEX feed, RAW adjustment, and `Sort.ASC`.
3. UTC-aware request and provider timestamp handling.
4. Pinned XNYS calendar schedule using `exchange-calendars==4.13.2`.
5. Whole-interval session containment.
6. Fixed canonical retained window.
7. At least 50 observed valid warm-up bars per symbol before `contract_start`.
8. Zero-tolerance missing expected slot behavior.
9. No synthetic bars, forward fill, backfill, or interpolation.
10. Fixed 27-column order and explicit Arrow schema.
11. Explicit PyArrow writer profile.
12. New v3.08 output identity, manifest, checksum, and run ID.
13. Fail-closed evidence for any mismatch.

## Proposed future tests

This is planning only. Likely future tests may include `tests/test_ppo_v2_dataset_reconstruction_contract.py`, but no tests are edited by this record.

Test areas:

1. Alpaca client, request, and retrieval literals:
   - `source_client = StockHistoricalDataClient`;
   - `request_class = StockBarsRequest`;
   - `retrieval_method = StockHistoricalDataClient.get_stock_bars`;
   - `source_client = alpaca.data.historical.StockHistoricalDataClient`;
   - `request_class = alpaca.data.requests.StockBarsRequest`;
   - mocked calls target `StockHistoricalDataClient.get_stock_bars`;
   - `TimeFrame.Hour`;
   - `DataFeed.IEX`;
   - `Adjustment.RAW`;
   - `Sort.ASC`;
   - `limit = None`;
   - `currency = None`;
   - `asof = None`; and
   - timezone-aware UTC request datetimes.
2. XNYS slot construction:
   - full regular sessions produce 6 eligible hourly slots;
   - 13:00 early-close sessions produce 3 eligible hourly slots;
   - holidays and non-sessions produce no expected gaps;
   - partial open/close edge bars are excluded unless fully contained; and
   - repeated schedule construction is deterministic.
3. Warm-up:
   - each symbol has at least 50 valid observed pre-contract bars;
   - insufficient warm-up fails closed; and
   - adaptive per-symbol starts are rejected.
4. Gap handling:
   - a missing expected slot fails closed;
   - duplicate `Symbol`/`Datetime` fails closed;
   - no forward fill, backfill, or interpolation occurs; and
   - gap evidence contains all required fields.
5. Schema:
   - exact 27-column order;
   - `Symbol` is UTF8/string and uppercase;
   - `Datetime` is `timestamp[ns, tz=UTC]`;
   - OHLCV and features are float64; and
   - no object dtype, null, NaN, or infinity exists.
6. Parquet writer:
   - PyArrow engine only;
   - explicit writer profile;
   - index is not serialized; and
   - unlisted kwargs are prohibited.
7. Dataset identity:
   - the old v3.07 path is prohibited as an output target;
   - the v3.08 superseding path is required; and
   - manifest, checksum, and run ID are required.
8. No network during unit tests:
   - Alpaca client calls are mocked;
   - no live API calls occur; and
   - no data fetching occurs in tests unless a future separate authorization allows it.

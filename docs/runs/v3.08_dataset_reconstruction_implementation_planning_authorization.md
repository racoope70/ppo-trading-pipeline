## Scope of the future implementation plan

The later implementation plan may propose, but not execute:

1. Required source files to create or modify.
2. Required tests to create or modify.
3. Required dependency or requirements changes.
4. Required runtime verification for `exchange-calendars==4.13.2` / `XNYS`.
5. Required command manifests.
6. Required data-generation boundaries.
7. Required fail-closed validation behavior.
8. Required evidence artifacts.
9. Required staging/commit sequence for future implementation.
10. Required independent review gates before any execution, data, or training step.

## Required implementation-planning constraints

The future implementation plan must explicitly account for:

1. `exchange-calendars==4.13.2` is not installed or runtime-verified yet.
2. Any dependency installation or requirements change requires separate authorization.
3. Runtime XNYS verification must occur before implementation authorization can be reconsidered.
4. Current source and tests do not implement the final prospective contract.
5. No Alpaca API calls or market-data fetching may occur during planning.
6. No dataset path may be created during planning.
7. No validation, preflight, or training may run during planning.
8. No model artifacts, orders, deployment, or tags may be created during planning.

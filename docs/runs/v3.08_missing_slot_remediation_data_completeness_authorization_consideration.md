## 5. Authorization options considered

### No remediation and keep dataset generation blocked

This remains the fail-closed fallback if the targeted provider request returns none or only some of the missing bars. It is safer than accepting incomplete data, but it does not test whether the identified common gaps are recoverable through a narrow governed request.

### Governed targeted refetch and raw data-completeness remediation

This option is supported. It directly addresses the likely provider/feed-level or upstream retrieval-completeness category while limiting access to the six governed symbols, IEX hourly RAW bars, two affected sessions, and exact missing expected observations. It preserves the original raw parquet and allows a separately named candidate only when actual provider-returned bars support one.

### Contract relaxation or calendar-rule change

Not authorized. The analysis reproduced the governed XNYS grid, found normal full sessions, and did not support a generally over-strict grid or calendar defect. The zero-missing-slot contract remains unchanged.

### Synthetic fill, interpolation, forward fill, or backfill

Not authorized. These actions would manufacture observations rather than recover provider-returned bars and conflict with the governed fail-closed contract.

### Full new raw-data fetch

Not authorized. The evidence identifies two bounded affected sessions; a complete historical refetch would exceed the least-privilege recovery scope currently supported.

### Dataset-generation re-execution

Not authorized. Recovery and completeness evidence must be produced and separately reviewed before dataset-generation authority can be reconsidered.

## 6. Authorization decision

# v1.72 PPO v2 Controlled Retraining Data Contract and Split Specification

## Purpose

Specify the data contract and time-series split rules required for a future PPO v2 controlled retraining path.

This specification is documentation only.

It does not authorize data generation, training execution, model artifact creation, paper orders, live orders, controlled submit, or hybrid deployment.

## Approved Universe

The approved PPO v2 retraining universe remains:

```txt
AAPL
AMD
MRK
PFE
UNH
XOM
```

Any expansion beyond this six-ticker universe requires a later checkpoint.

## Raw Data Contract

Required raw columns:

```txt
Datetime
Symbol
Open
High
Low
Close
Volume
```

Optional raw columns:

```txt
TradeCount
VWAP
```

Required row grain:

```txt
one row per Symbol per Datetime bar
```

Required timeframe:

```txt
1-hour bars
```

Required ordering:

```txt
Symbol ascending
Datetime ascending within Symbol
```

Required uniqueness:

```txt
no duplicate Symbol-Datetime rows
```

## Data Validation Rules

Future implementation must validate:

```txt
all required columns exist
Datetime is parseable
Symbol is non-null
Symbol belongs to the approved universe
OHLC fields are numeric
Volume is numeric
OHLC fields are non-negative
Volume is non-negative
High >= Low
High >= Open
High >= Close
Low <= Open
Low <= Close
duplicate Symbol-Datetime rows do not exist
rows are time ordered within Symbol
missing bars are measured and reported
```

## Feature Contract

Features must be trailing-only.

Allowed feature families:

```txt
lagged return features
rolling mean features
rolling volatility features
rolling momentum features
rolling volume features
rolling technical indicators
trailing regime indicators
```

Forbidden feature families:

```txt
future return features
future volatility features
future drawdown features
post-outcome labels
holdout-derived features
evaluation-derived features
features fit on the full dataset
features requiring future observations
```

## Forbidden PPO Observation Columns

These columns must be excluded from PPO model inputs:

```txt
Target
Return
Datetime
Symbol
```

Allowed non-model use:

```txt
Datetime = indexing, split validation, audit logging
Symbol = grouping, split validation, audit logging
Target = supervised labels only if used in a separate approved process
Return = audit metric only unless later approved
```

## Time-Series Split Contract

Random split construction is prohibited.

Future PPO v2 data must be split in time order:

```txt
train_df
embargo
eval_df
holdout_df
```

Split definitions:

```txt
train_df = model fitting and train-only preprocessing fit
embargo = unused time gap between train and evaluation
eval_df = model selection and validation
holdout_df = final untouched out-of-sample validation
```

## Embargo Rule

An embargo must separate train and eval.

Minimum embargo rule:

```txt
embargo_window >= max(feature_lookback_window, target_horizon, execution_delay_window)
```

If the maximum lookback, target horizon, or execution delay cannot be determined, the pipeline must fail closed.

## Holdout Rule

The holdout set must be final-validation only.

The holdout set must not be used for:

```txt
feature selection
hyperparameter tuning
reward tuning
threshold tuning
model selection
normalizer fitting
scaler fitting
regime fitting
manual iteration
```

## Preprocessing Rule

Preprocessing must be fit on `train_df` only.

Train-only preprocessing includes:

```txt
scaling
normalization
imputation
winsorization
PCA
regime model fitting
volatility threshold fitting
feature bucket fitting
```

The fitted preprocessing object may transform `eval_df` and `holdout_df`.

Evaluation and holdout data must not influence fitted preprocessing parameters.

## Leakage Rejection Rules

Future implementation must reject:

```txt
future information leakage
cross-split leakage
holdout leakage
target leakage
normalization leakage
feature engineering leakage
duplicate timestamp leakage
symbol aggregate leakage
```

# v1.64 PPO Promotion Standard / Acceptance Criteria

## Purpose

Define the evidence required before any PPO model can be promoted beyond infrastructure/audit use.

## Background

v1.60 reclassified the current PPO model as a legacy baseline / infrastructure validation fixture.

v1.61 defined the audit scope.

v1.62 inventoried artifacts.

v1.63 completed the model-quality audit and concluded:

```text
infrastructure_baseline_decision = PASS_FOR_INFRASTRUCTURE_BASELINE
trading_edge_decision = FAIL_FOR_TRADING_EDGE
controlled_submit_decision = REJECT_FOR_CONTROLLED_SUBMIT
retraining_review_posture = ELIGIBLE_FOR_RETRAINING_DESIGN_REVIEW_ONLY_AFTER_v1.64_AND_v1.65
```

## Core Principle

A PPO model cannot be promoted because the pipeline works.

A PPO model cannot be promoted because artifacts exist.

A PPO model cannot be promoted because Sharpe is positive.

A PPO model cannot be promoted because it beats cash only.

A PPO model cannot be promoted because feature importance looks plausible.

A PPO model can only be promoted when offline evidence, benchmark evidence, risk evidence, robustness evidence, and no-submit behavior all support promotion.

## Promotion Levels

## Level 0 - Infrastructure Baseline

Purpose:

```text
Validate artifact loading, feature alignment, prediction, broker connectivity, reporting, diagnostics, and NO-SUBMIT safety behavior.
```

Required:

```text
complete artifact set
passing tests
passing reporting chain
no order submission by default
clear run logs
clear diagnostics
versioned documentation
```

Does not prove:

```text
trading edge
controlled-submit readiness
live-trading readiness
```

Current legacy PPO status:

```text
PASS_FOR_INFRASTRUCTURE_BASELINE
```

## Level 1 - Offline Model Quality Candidate

Purpose:

```text
Determine whether the model has enough offline evidence to justify no-submit observation.
```

Required:

```text
complete artifact set for each selected symbol
model_info available
walk-forward evidence available
cash/no-trade baseline comparison
buy-and-hold benchmark comparison
net-of-cost performance
slippage assumptions documented
drawdown documented
turnover documented
Sharpe documented
profit factor or trade-level evidence documented if available
embargo/leakage controls documented
selection logic documented
no single-window cherry-picking
stable evidence across adjacent windows or repeated folds
```

Minimum acceptance:

```text
beats cash/no-trade baseline after costs
beats buy-and-hold after costs in a majority of evaluated windows
positive median PPO-vs-buy-and-hold result across selected windows
no single selected window can be the only support for promotion
drawdown must be acceptable relative to return
turnover and cost assumptions must not erase edge
leakage/embargo controls must be documented and passed
```

Hard blockers:

```text
missing model_info
missing benchmark fields
underperforms buy-and-hold in most complete windows
positive Sharpe but negative PPO-vs-buy-and-hold median
unclear leakage/embargo controls
unclear cost/slippage assumptions
selection based only on best Sharpe window
unexplained high drawdown
unexplained high turnover
```

Current legacy PPO status:

```text
FAIL_FOR_TRADING_EDGE under v1.63
```

## Level 2 - No-Submit Observation Candidate

Purpose:

```text
Observe live paper-market behavior without submitting orders.
```

Required:

```text
Level 1 pass
NO-SUBMIT default
fresh paper-market data
broker connectivity pass
risk checks pass
pre-trade checklist pass
prediction diagnostics pass
candidate logs saved
execution plan logs saved
zero orders submitted
clear classification of SINGLE_NEW_CANDIDATE, MULTI_ORDER_PLAN, or NO_TRADE_PLAN
candidate behavior stable across observation cycles
```

Minimum acceptance:

```text
no broker-side errors
no missing feature errors
no artifact mismatch errors
no unexplained prediction failures
candidate set stability established
no unresolved multi-order instability
candidate recurrence must be clean enough to support future controlled-submit review
no-submit reports must remain reproducible
```

Hard blockers:

```text
multi-order instability
candidate set changes materially across cycles
no clean candidate persistence
broker errors
risk-check failures
pre-trade checklist failures
feature mismatch
artifact mismatch
orders submitted during no-submit mode
```

Current legacy PPO status:

```text
Historical no-submit evidence did not establish candidate-set stability.
```

## Level 3 - Controlled-Submit Eligible Candidate

Purpose:

```text
Allow a future separate checkpoint to consider very limited paper order submission.
```

Required:

```text
Level 1 pass
Level 2 pass
explicit controlled-submit checkpoint
documented submit limits
position-size cap
notional cap
symbol whitelist
kill switch
paper-only confirmation
broker account confirmation
open-order check
cash/equity tolerance check
manual review before submit
post-submit reconciliation plan
rollback / flattening plan
order log validation
no live-trading keys
```

Minimum acceptance:

```text
single-candidate or stable candidate set
risk checks pass
pre-trade checklist pass
expected notional within cap
no unresolved multi-order instability
orders limited to predefined symbols
paper-only mode verified
submit explicitly authorized in a separate checkpoint
```

Hard blockers:

```text
no explicit controlled-submit checkpoint
multi-order instability
candidate instability
missing paper-only verification
unbounded order size
missing kill switch
missing reconciliation
missing rollback plan
any live-trading configuration risk
```

Current legacy PPO status:

```text
REJECT_FOR_CONTROLLED_SUBMIT
```

Purpose:

```text

```

Required:

```text

slippage analysis
fill-quality analysis
drawdown monitoring
model drift monitoring
feature drift monitoring
broker reliability history
incident response plan
capital allocation plan
live risk limits
human approval checkpoint
separate live-trading authorization milestone
```

Minimum acceptance:

```text
controlled paper-submit phase completed without safety exceptions
realized performance supports the offline and no-submit evidence
slippage and fill quality remain within documented assumptions
drawdown remains within live-risk tolerance
model and feature drift monitoring are active
incident response procedures are documented and reviewed
capital allocation and live risk limits are explicitly approved
live trading is authorized only by a separate milestone
```

Hard blockers:

```text
no successful controlled paper-submit phase
unresolved slippage or fill-quality issues
unresolved drawdown or drift concerns
missing incident response plan
missing live risk limits
missing human approval checkpoint
missing separate live-trading authorization milestone
any live-trading configuration risk
```

Current project status:

## Acceptance Criteria Summary

A PPO model may advance from infrastructure baseline to offline model quality candidate only when:

```text
artifact completeness is confirmed
benchmark evidence is complete
cash baseline is beaten after costs
buy-and-hold is beaten after costs in a majority of relevant windows
median PPO-vs-buy-and-hold is positive
drawdown is documented and acceptable
turnover is documented and cost-adjusted
leakage and embargo controls are documented
selection logic is not dependent on a single best Sharpe window
```

A PPO model may advance from offline model quality candidate to no-submit observation only when:

```text
offline audit passes
artifact compatibility passes
prediction diagnostics pass
risk assumptions are documented
NO-SUBMIT remains default
no order submission is possible without separate authorization
```

A PPO model may advance from no-submit observation to controlled-submit eligibility only when:

```text
no-submit behavior is stable
candidate recurrence is clean
multi-order instability is resolved
broker checks pass
risk checks pass
submit limits are defined
paper-only mode is verified
a separate controlled-submit checkpoint authorizes it
```

## Rejection Criteria

Reject or block promotion when:

```text
buy-and-hold outperforms PPO in most complete windows
median PPO-vs-buy-and-hold is negative
candidate set is unstable
multi-order instability remains unresolved
the model only beats cash
feature importance is used as edge proof
artifact completeness is mistaken for trading readiness
Sharpe is used without benchmark and drawdown context
transaction costs are missing
slippage assumptions are missing
leakage/embargo controls are missing
controlled submit is requested without a separate checkpoint
```

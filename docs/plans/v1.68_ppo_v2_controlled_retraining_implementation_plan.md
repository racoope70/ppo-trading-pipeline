# v1.68 PPO v2 Controlled Retraining Implementation Plan

## Purpose

Define the controlled implementation plan for future PPO v2 retraining.

v1.68 translates the v1.66 design and v1.67 authorization review into a concrete implementation plan.

This is not an implementation milestone.

This is not a retraining-execution milestone.

This is not a model-artifact milestone.

This is not a paper-order milestone.

This is not a hybrid-deployment milestone.

## Planned Implementation Structure

The future implementation should be organized into separate layers:

```text
configuration layer
data-validation layer
split-validation layer
feature-manifest validation layer
training-safety layer
artifact-governance layer
reporting-plan layer
runbook layer
approval-gate layer
```

Each layer must be testable before retraining execution is authorized.

## Planned Configuration Layer

The future PPO v2 configuration should define:

```text
data source
ticker universe
bar timeframe
train period
embargo period
evaluation period
holdout period
feature manifest
cost assumptions
slippage assumptions
turnover assumptions
artifact root
report root
random seed policy
training execution safety flag
```

Required default:

```text
training_execution_enabled = false
```

No future implementation should allow training to run by default.

## Planned Data-Validation Layer

The future data-validation layer should check:

```text
source provenance
timestamp coverage
symbol coverage
missing bars
duplicate bars
market-session alignment
unexpected nulls
unexpected symbols
unexpected columns
```

Generated datasets must not be created until a later checkpoint explicitly authorizes them.

## Planned Split-Validation Layer

The future split-validation layer should verify:

```text
train_df starts and ends before embargo
embargo separates train and eval
eval_df does not overlap train_df
holdout_df does not overlap train_df
holdout_df does not overlap eval_df
holdout_df remains unused for tuning
```

The split-validation layer must fail if temporal overlap is detected.

## Planned Feature-Manifest Validation Layer

The future feature layer must preserve the safe feature manifest.

Forbidden model input fields:

```text
Target
Return
Datetime
Symbol
```

Permitted use of those fields:

```text
labeling
evaluation
grouping
auditing
reporting
```

Feature additions require leakage review before use.

## Planned Training-Safety Layer

The future training-safety layer must enforce:

```text
training disabled by default
manual approval required before execution
no model artifacts without approval
no generated datasets without approval
no overwrite of legacy PPO artifacts
no overwrite of validated artifacts
no accidental paper-trading authorization
```

Training execution must require a later checkpoint.

## Planned Artifact-Governance Layer

The future implementation must define isolated artifact paths.

Required artifact categories:

```text
raw data path
processed data path
training output path
model artifact path
walk-forward report path
holdout report path
audit summary path
log path
```

Artifact rules:

```text
generated datasets remain ignored
model artifacts remain ignored
large reports remain ignored
logs remain ignored unless intentionally documented
credentials are never committed
legacy PPO artifacts are never overwritten
validated artifacts are never overwritten
```

## Planned Reporting Layer

The future reporting plan should define expected report categories without creating them:

```text
data validation summary
split validation summary
feature validation summary
walk-forward summary
benchmark comparison summary
risk and robustness summary
holdout summary
artifact inventory summary
retraining audit summary
```

v1.68 does not create these reports.

## Planned Benchmark Requirements

Future PPO v2 retraining must compare against:

```text
cash / no-trade baseline
buy-and-hold baseline
equal-weight portfolio baseline where applicable
legacy PPO infrastructure baseline where applicable
```

Promotion cannot rely on:

```text
positive Sharpe alone
cash outperformance alone
one favorable window
one favorable symbol
feature importance
```

A later implementation scaffold should include tests for:

```text
configuration safety

artifact path isolation
generated path exclusion
safe feature manifest behavior
split non-overlap
embargo enforcement
holdout isolation
train-only preprocessing
no paper-order side effects
no broker-order side effects
```

## Planned Runbook Requirements

The future runbook should include:

```text
pre-run checklist
configuration checklist
data checklist
split checklist
feature checklist
artifact checklist
test checklist
manual approval checklist
post-run audit checklist
rollback checklist
cleanup checklist
```

The runbook must not include a live training command until a later checkpoint explicitly authorizes retraining execution.

## Planned Approval Sequence

The intended future sequence is:

```text
v1.68 PPO v2 Controlled Retraining Implementation Plan
-> future implementation scaffold review
-> future configuration and test review
-> future retraining execution authorization review
-> future controlled retraining execution
-> future offline model-quality audit
-> future holdout validation review
-> future no-submit paper-trading observation
-> future controlled-submit eligibility review
```

The path must not skip directly from planning to paper trading.

## Explicit Non-Authorizations

## Implementation Rejection Criteria

Reject or redesign a future implementation if:

```text
training can run by default
data generation can run by default
model artifacts can be created without approval
legacy artifacts can be overwritten
validated artifacts can be overwritten
holdout isolation is unclear
embargo enforcement is missing
feature leakage checks are missing
artifact paths are ambiguous
tests are missing
paper-order authorization is implied
hybrid deployment is implied
```

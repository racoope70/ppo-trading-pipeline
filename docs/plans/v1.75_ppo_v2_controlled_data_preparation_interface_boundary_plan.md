## Future Interface Objective

The future data-preparation interface should prepare raw in-memory data into split-specific PPO v2 data structures without fetching external data, writing generated datasets, training models, or creating model artifacts.

The future interface should be limited to deterministic validation, split assignment, feature-column selection, preprocessing-fit boundary enforcement, holdout-policy enforcement, and metadata reporting.

## Planned Inputs

```txt
raw_df
split_boundary_spec
approved_symbol_universe
required_raw_columns
forbidden_observation_columns
preprocessing_fit_split
holdout_usage_policy
```

The future interface must assume raw data already exists.

The future interface must not download raw data.

The future interface must not create raw data.

The future interface must not write generated datasets unless a later checkpoint explicitly authorizes dataset creation.

## Forbidden Observation Inputs

The following columns must not enter PPO observation inputs:

```txt

Return
Datetime
Symbol
```

These columns may be retained only for labeling, evaluation, grouping, auditing, lineage, and reporting.

## Planned Output Boundary

A future implementation may define an output object or dictionary with the following conceptual outputs:

```txt
train_df
eval_df
holdout_df
observation_columns
data_contract_errors
split_boundary_errors
holdout_policy_errors
preprocessing_boundary_errors
validation_metadata
```

The future interface must not output trained models.

The future interface must not output model artifacts.

The future interface must not output broker orders.

The future interface must not output controlled-submit commands.

## Split Boundary Requirements

The future interface must enforce:

```txt
train_df ends before eval_df starts
required embargo gap exists between train_df and eval_df
eval_df ends before holdout_df starts
holdout_df remains untouched for final validation only
no temporal overlap exists between train_df, eval_df, and holdout_df
```

## Preprocessing Boundary Requirements

The future interface must enforce:

```txt
preprocessing fit split = train_df only
eval_df uses train-fitted preprocessing only
holdout_df uses train-fitted preprocessing only
no scaler fitting on eval_df
no scaler fitting on holdout_df
no feature selection on holdout_df
no hyperparameter tuning on holdout_df
no reward tuning on holdout_df
no threshold tuning on holdout_df
no model selection on holdout_df
```

## Validation Dependency

A future implementation must reuse or remain consistent with:

```txt
src/ppo_v2_data_contract.py
tests/test_ppo_v2_data_contract.py
```

The v1.73 validation utilities remain the reference layer for:

```txt

observation-column validation

```

## Prohibited Future Interface Behavior Unless Separately Authorized

```txt
joblib artifact writing

live-order submission
controlled-submit activation
hybrid model activation
```

## Required Safety Posture

The future data-preparation interface must fail closed.

Required future behavior:

```txt
invalid data contract -> return errors / fail closed
invalid split boundary -> return errors / fail closed
invalid holdout usage -> return errors / fail closed
invalid preprocessing boundary -> return errors / fail closed
forbidden observation columns present -> return errors / fail closed
approved universe violation -> return errors / fail closed
```

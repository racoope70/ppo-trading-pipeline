## Training Input Handoff Boundary

A future training-input handoff layer may accept only a valid in-memory data-preparation integration result.

The future handoff layer may not fetch market data.

The future handoff layer may not read CSV files.

The future handoff layer may not read parquet files.

The future handoff layer may not write generated datasets.

The future handoff layer may not fit preprocessing on evaluation or holdout data.

The future handoff layer may not train PPO.

The future handoff layer may not create model artifacts.

The future handoff layer may not submit orders.

## Approved Future Handoff Input

A later scaffold may accept a conceptual input shaped around:

```txt
data_preparation_integration_result = valid PPOV2DataPreparationIntegrationResult only
train_df = in-memory training split from data-preparation result
eval_df = in-memory evaluation split from data-preparation result
holdout_df = in-memory holdout split from data-preparation result
observation_columns = approved observation-column tuple
run_identifier = metadata only
execution_mode = dry_run / validation_only only
handoff_metadata = metadata only
```

The handoff must reject any input where:

```txt
data_preparation_integration_result.is_valid is False
data_preparation_integration_result.data_preparation_result is None
train_df is missing
eval_df is missing
holdout_df is missing
observation_columns is empty
forbidden observation columns are present
holdout is requested for training
holdout is requested for model selection
```

## Risk Controls

The main risk is accidentally treating prepared data as authorization to train.

The control is to separate data-preparation validity from training authorization.

A valid handoff may prove that the data is shaped correctly for a future training boundary, but it does not authorize training.

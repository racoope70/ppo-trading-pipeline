### F-01 — Import-time side-effect boundary is not fully explicit

The draft broadly prohibits environment-value, credential, network, provider, market-data, and other unauthorized activity and says a probe producing unexpected runtime activity must stop. It does not, however, explicitly state that an import must not begin, or must fail closed before the prohibited access occurs, if import-time behavior would access each required category, including **external configuration**. External-configuration access is not expressly named in the import-time boundary. Because all relevant activity maxima are zero, classifying after the side effect occurs cannot cure the exceeded boundary.

The authorization should explicitly require a pre-probe fail-closed determination for import-time access to environment-variable values, credentials, network, provider, market data, or external configuration, with no probe when that safety cannot be established. Harmless interpreter/process environment mechanics may be distinguished from prohibited inspection or retrieval of environment-variable values.
